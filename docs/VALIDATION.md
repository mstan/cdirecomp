# Validation boundaries

Run the source-only CTest suite from the repository root. It covers disc/OS-9 validation, emitted position-independent code, overlapping function entries, BIOS output placement, module binding, instruction arithmetic, peripherals, NVRAM, video parity, input, audio and player preferences. Synthetic fixtures require no copyrighted inputs.

Built-game checks belong to the consumer. Use isolated settings and saves, normal-speed deterministic workloads and the TCP interface. Compare complete guest state, relevant events, audio and completed frames against the reference implementation. Retain exact source/binary identities and raw evidence outside tracked source.

Hotel Mario's published v0.0.3 preview qualified selected native jobs and a bounded gameplay workload through field 13,000. That evidence does not certify complete campaigns, every stage, audio listening quality or correct game-save restoration. The consumer documents its current limits.

Historical campaign evidence remains retained in the private central tracker and its recorded evidence locations. Current task state is maintained there rather than in duplicated repository session ledgers.
